# TableFlash — Product Rules

TableFlash is a mobile-first SaaS for restaurants.

The primary users are restaurant owners and staff using phones and tablets during service.

## Product vision

TableFlash must help restaurants:

1. Create their menu
2. Generate QR codes by table
3. Receive orders
4. Track orders
5. Ask for reviews after meals
6. See important numbers
7. Configure the restaurant easily

Anything that does not directly support these goals must be:

- removed
- simplified
- postponed
- or hidden in advanced settings

The restaurant owner must never feel like they are using complicated software.

## Core priorities

1. Mobile and tablet usability
2. Restaurant operational clarity
3. Fast actions
4. No visual bugs
5. No unnecessary features
6. Desktop is secondary

## MVP scope

Keep:

- QR menu
- Table ordering
- Physical payment only
- Orders dashboard
- QR by table
- Reviews after meals
- Google reviews redirection
- Simple statistics
- Restaurant settings
- Product images
- Simple promotions
- Product availability / out of stock

Do not add yet:

- Supabase
- Auth
- Stripe
- Database
- Online payment
- Multi-restaurant
- Staff roles
- Kitchen printing
- PDF export
- Advanced analytics
- Sound notifications
- Kitchen mode

## Forbidden UI wording

Never show these words in the restaurant or customer interface:

- mock
- demo
- local
- backend
- fake
- placeholder
- test data

Use user-facing wording instead:

- activité du jour
- commandes récentes
- données de service
- aperçu
- configuration
